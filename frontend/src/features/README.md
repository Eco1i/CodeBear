# 前端业务边界

`features/` 按业务域组织码熊前端中可独立演进的代码：

- `workspace`：项目、目录、PDM 导入、回收站和工作区设置。
- `tables`：表检索、详情与字段保存。
- `ai`：AI 设置、对话、检索范围和布局状态。
- `backup`：备份导出、检查、迁移与树选择逻辑。
- `ddl`：DDL 目录、目标数据库配置和脚本生成。
- `shell`：只负责组合业务模块，不承载业务规则。

各业务域将接口访问放在 `api.ts`、纯数据规则放在 `model.ts`、领域类型放在
`types.ts`。跨业务复用的 HTTP 基础能力位于 `shared/api/`。功能组件可以继续拆分，
但不得从一个业务域直接引用另一个业务域的内部实现；跨域数据通过公开类型和组件
属性传递。根目录的 `api.ts` 与 `types.ts` 仅作为兼容入口，新代码应优先引用所属业务域。

样式从单一 `styles.css` 拆分到 `styles/`：`base` 保存全局基础和滚动条，`shell`
保存应用壳，`workspace`、`tables`、`ai`、`backup`、`ddl` 分别保存对应业务样式。
`styles/index.css` 的导入顺序等同于拆分前的级联顺序，不得随意调整；新样式应写入
所属业务文件，避免重新形成跨业务全局样式堆积。
